# Risk Register

This document tracks known risks to the project, evaluating their likelihood, impact, and specifying mitigation strategies.

| Risk ID | Description | Likelihood | Impact | Mitigation Strategy | Owner | Status | Timeline |
|---------|-------------|------------|--------|---------------------|-------|--------|----------|
| **RISK-001** | **IFCT PDF parsing complexity:** IFCT data is provided as complex PDFs without a structured API, increasing the risk of data extraction errors. | High | High | Dedicated PDF extraction pipeline implemented for IFCT 2017 Table 1 with row-count, duplicate, numeric, mass-balance, hash, and golden-query validation. Micronutrient table extraction remains a Phase 8 risk. | Data Team | Mitigated for Phase 2 | Phase 2 / Phase 8 |
| **RISK-002** | **Exercise library data licensing:** Securing a comprehensive, high-quality exercise dataset that allows commercial use without restrictive licensing. | Medium | Medium | Audit open-source datasets (e.g., wger), verify licenses. Seed only permissive data; rely on users to create custom exercises otherwise. | Legal/Data | Active | Phase 3 |
| **RISK-003** | **Mid-range Android performance:** SQLite operations, FTS queries, and complex UI rendering might exceed the performance budget on lower-end devices. | High | High | Implement strict pagination, debounce UI inputs, optimize SQLite indexes, and use React Native performance profiling tools constantly. | Engineering | Active | Ongoing |
| **RISK-004** | **Expo SDK major version breakage:** Upgrading Expo SDKs historically introduces breaking changes in native modules and build pipelines. | Medium | High | Lock SDK versions during major development phases. Test upgrades in isolated branches. Maintain a rollback plan. | DevOps | Monitored | Ongoing |
| **RISK-005** | **Sync conflict edge cases:** Handling data conflicts caused by clock skew or devices being offline for weeks. | Low | High | Use server-side timestamps as the source of truth for conflict resolution. Implement CRDT-like last-write-wins per column. | Backend Eng | Active | Phase 7 |
| **RISK-006** | **Workout recovery reliability:** Android's aggressive background app killing could cause data loss during workouts. | High | High | Persist workout state to SQLite instantly on every set completion. Implement robust resume-on-launch logic. | Mobile Eng | Active | Phase 3 |
| **RISK-007** | **AGPL compliance for app stores:** Use of AGPL libraries might conflict with Apple App Store / Google Play Store terms or require open-sourcing the proprietary app. | Medium | Critical | Strictly audit all dependencies for AGPL/GPL licenses. Only allow MIT, Apache 2.0, BSD, or commercial licenses in the main bundle. | Legal | Active | Phase 1 |
| **RISK-008** | **Scope creep:** Adding features beyond the planned phases, delaying release and diluting the core value proposition. | High | Medium | Strictly adhere to `PLAN.md` and phase gates. Defer all non-essential features to Phase 12 (Post-Launch). | Product | Monitored | Ongoing |
| **RISK-009** | **Indian food ontology completeness:** Missing regional foods or incorrect macro data for Indian cuisine leading to poor user trust. | Medium | High | Phase 2 ships 528 IFCT Table 1 foods, 100+ aliases, user foods, and household recipes. Regional expansion, evaluation, and dietitian review continue in Phase 9 and release work. | Content Team | Mitigated for Phase 2 | Phase 2 / Phase 9 |
| **RISK-010** | **Single developer bus factor:** Project relies heavily on a single developer, risking complete halt if they become unavailable. | Low | High | Maintain rigorous, implementation-grade documentation (this folder). Ensure CI/CD pipelines are fully automated and documented. | Management | Monitored | Ongoing |
| **RISK-011** | **API cost management:** Third-party AI and search APIs scaling costs linearly with user growth, potentially ruining unit economics. | Medium | High | Implement aggressive local caching. Fall back to smaller, cheaper models where possible. Cap daily API usage per user. | Engineering | Active | Phase 6 |
| **RISK-012** | **Schema migration breaking user data:** A malformed migration corrupting local SQLite databases on upgrade. | Low | Critical | Mandate round-trip backup/restore testing for every schema version. Enforce strict `EXPORT_TABLES` testing in CI. | DB Admin | Active | Ongoing |
